# 골프 교정 데이터 준비와 Colab 학습

> 이전 지도자 정답 기반 실험 안내입니다. 현재 앱 사용에 지도자 승인은 필요하지 않습니다. 현재 절차는 `EVIDENCE_COACHING.md`와 `golf_evidence_inference.ipynb`를 사용하세요.

현재 앱 측정·검토용 자료 수집 기능과 Colab 학습 노트북이 준비되어 있습니다. 실제 교정 SLM을 학습하거나 앱에 탑재하지 않았습니다.

## 앱 사용

1. 촬영 방향·주사용 손·클럽을 지정합니다.
2. 영상에서 어드레스/탑/임팩트/피니시를 확인합니다.
3. 샷 기록을 첨부하거나 건너뛰어 분석 결과로 이동합니다.
4. 자세별 접이식 카드에서 수치를 확인합니다.
5. `지도자 검토용 데이터 내보내기`를 눌러 원하는 위치에 JSON을 저장합니다.

JSON은 원본 영상이나 휴대폰 파일 경로를 포함하지 않습니다. 지도자가 영상을 검토하려면 별도로 해당 영상과 record_id를 연결해 관리하세요. 앱 내 기록은 현재 실행 세션에 보관되므로 필요한 자료는 종료 전에 내보내세요. 촬영 영상의 갤러리 저장과는 별개입니다.

## 수치 정의와 한계

- 네 자세별 리드/트레일 팔꿈치, 리드/트레일 무릎, 몸통 기울기: 총 20개 레코드.
- 오른손 스윙의 리드 측은 왼쪽, 왼손 스윙의 리드 측은 오른쪽입니다.
- 팔꿈치는 어깨–팔꿈치–손목, 무릎은 엉덩이–무릎–발목의 영상상 내각입니다. 펴진 상태는 약 180°입니다.
- 몸통은 양쪽 어깨 중점과 엉덩이 중점을 연결한 선입니다. 화면 수직 위쪽을 0°, 오른쪽을 +로 표시합니다. 해부학적 척추 각도나 실제 3D 전경각이 아닙니다.
- 원본 영상의 선택 시각에서 가장 가까운 프레임을 다시 추출해 ML Kit로 검출합니다. 실제 디코딩된 프레임 PTS는 아직 얻지 못하므로 `video_pts_synchronized=false`입니다. 임팩트의 시간 오차는 여전히 남을 수 있습니다.
- 관절 likelihood 0.7 이상, 선분 길이 화면 대각선 1% 이상 조건은 수치 안정성을 위한 임시 품질 기준입니다. 교정 판정 기준이나 정확도 확률이 아닙니다.
- 가림/검출 실패/영상 밖 관절/짧은 선분/시각 불일치는 `value:null`, `status:unavailable`, 사유로 남습니다. 0°로 대체하지 않습니다.
- 실제 체중 분포, 클럽 페이스, 3D 회전, 머리 이동의 원인과 교정 정상 범위는 이 버전에서 계산하지 않습니다.

## 지도자 검토 양식

내보낸 JSON을 복사하여 다음 필드를 채웁니다. 실제 검토 없이 approved로 바꾸지 마세요.

| 필드 | 입력 내용 |
|---|---|
| golfer_id | 실명이 아닌 동일 골퍼의 고정 식별자 |
| session_id | 동일 촬영 세션의 고정 식별자 |
| training_consent | 데이터 사용 동의가 확보된 경우만 true |
| review.status | pending / approved / rejected |
| review.reviewer_id | 지도자 식별자 |
| review.reviewed_at | ISO 8601 검토 시각 |
| review.decision | observation_only / correction / cannot_assess |
| review.evidence_metric_ids | 근거가 되는 metrics의 id 목록 |
| review.observation | 수치/영상에서 확인되는 관찰 |
| review.correction | 우선 교정 항목 1개, 없으면 null |
| review.drill_id | 검토된 연습 자료의 고정 ID, 없으면 null |
| review.drill_instructions | 해당 연습 방법, 없으면 null |
| review.cannot_assess_reason | 판단 불가 사유, 해당 없으면 null |

수치만으로 문제라고 단정할 수 없는 경우 observation_only 또는 cannot_assess를 선택합니다. correction에는 유효한 측정 근거와 지도자가 검토한 연습 방법이 필요합니다. 자동 검사는 양식과 근거 ID만 확인할 수 있고 교정 내용의 타당성을 보장하지 않습니다.

## Colab용 데이터 변환

승인된 JSON만 별도 `reviewed` 폴더에 모은 뒤 실행합니다. Python 3.10 이상, 추가 설치 없음.
`prepare_coaching_dataset.py`와 `coaching_training_helpers.py`를 같은 폴더에 두세요.

```bash
python prepare_coaching_dataset.py reviewed prepared_v1
```

생성 파일: train.jsonl / validation.jsonl / test.jsonl / manifest.json.
동일 골퍼 또는 동일 촬영 세션이 하나라도 연결되면 같은 그룹으로 묶어 학습/검증/평가 누출을 막습니다. 독립 그룹 최소 3개가 필요하며, 이 최소 개수는 학습 품질 기준이 아닙니다. 그룹 수 기준 약 80/10/10으로 나누므로 레코드 수 비율은 달라질 수 있습니다.

동의 누락, 미검토 자료, 측정 불가 값을 교정 근거로 사용한 자료, 중복 자료가 있으면 변환을 중단합니다. 출력 폴더를 덮어쓰지 않습니다. 테스트용 가짜 정답은 실제 학습 자료에 포함하지 마세요.

## Colab 노트북 사용

1. `golf_coaching_qlora.ipynb`를 Colab의 파일 → 노트북 업로드로 엽니다.
2. 지도자가 검토하고 승인한 앱 JSON 여러 개를 준비합니다. 실명 대신 골퍼·촬영 세션 식별자를 사용하세요.
3. 노트북을 위에서 아래로 실행합니다. 데이터 검증을 통과해야 모델 다운로드/학습으로 진행합니다.
4. GPU 런타임에서 기준 모델 평가 → QLoRA 학습 → 검증/테스트 비교를 실행합니다.
5. 결과 ZIP에는 어댑터, 생성 답변, 기준 정답, 검사 결과, 버전 정보가 담깁니다.
6. GGUF가 필요할 때만 마지막 선택 셀의 `EXPORT_GGUF=True`를 설정합니다. 변환 도구는 별도 Python 환경에 설치해 학습 환경과 분리합니다.

Colab에 올리는 JSON은 Google Colab 환경으로 전송됩니다. 노트북은 원본 영상 업로드나 Hugging Face Hub 게시를 수행하지 않습니다.
예제 JSON은 실제 앱에서 내보낸 **검토 대기 자료**입니다. 학습 정답 예제가 아니며 검증에 실패하는 것이 정상입니다.

노트북은 검증 도구를 내장하므로 ipynb 파일 하나로 시작할 수 있습니다. 모델 다운로드 및 GPU 학습, GGUF 변환은 이 PC에서 실행하지 않았습니다.

## 모델 입력 계약

원본 검토 JSON을 `coaching_training_helpers.model_input`으로 변환하여 `golf_coaching_input_1.0` 입력을 만듭니다.
반복되는 관절 이름/표시용 필드는 생략하되 각도, 측정 불가 사유, 관절 신뢰도, 촬영 방향, 시각 정보와 2D/PTS 한계는 유지합니다.
향후 앱의 SLM 연결에서도 같은 변환과 비추론 chat template를 사용해야 합니다. 이번 단계에서는 앱의 실제 SLM 실행기를 추가하지 않았습니다.

자동 평가의 JSON 유효율·근거 ID 일치율·판단 유보율은 교정 내용의 정확도나 폰 성능이 아닙니다. 입력에 없는 각도 표현은 검토 대상으로 표시하지만 문장의 모든 오류를 자동 검출하지는 못합니다.
